# 后端质量基准

后端糟糕的根因通常是「契约没定就写实现」「只考虑正常输入」「事务与并发靠运气」。本文件规定设计阶段必须产出什么、实现必须达到什么、交付前必须怎么验证。

## 设计阶段产出要求（写入 design.md「后端设计」与「接口契约」）

每个涉及接口或数据的模块必须写全以下内容：

1. **分层与职责**：遵循项目现有分层（如 controller / service / repository 或 handler / usecase / adapter），写出本模块每层新增的类/文件及职责
2. **数据模型**：表/集合名、字段（类型、必填、默认、唯一、索引）、外键与关系、软删除策略、迁移脚本位置与回滚方式
3. **状态机**：状态枚举、迁移条件、触发者、不可逆点、非法迁移的错误码
4. **接口契约**（每个接口）：方法与路径、鉴权与权限点、请求参数（类型/必填/范围/默认）、请求与响应示例、错误码表、幂等性（幂等键或天然幂等）、分页/排序/筛选参数与上限
5. **事务边界**：哪些操作在一个事务内；跨服务/跨表的最终一致性方案
6. **并发与幂等**：重复提交、并发修改（乐观锁/悲观锁/版本号）、竞态场景
7. **校验规则**：参数校验、业务规则校验、与前端校验的一致性
8. **错误处理**：统一错误结构、错误码命名规则（与 `module-common` 一致）、哪些错误记日志哪些告警
9. **性能边界**：预期数据规模、分页上限、批量操作上限、慢查询预案、缓存策略与失效
10. **外部依赖**：第三方服务、消息队列、定时任务、文件存储；超时、重试、降级策略
11. **安全**：鉴权、越权检查（资源归属）、输入清洗、敏感字段脱敏、审计日志
12. **测试策略**：单测覆盖的业务规则、接口测试覆盖的正反例、需要的测试数据

## 实现基准

结构：

- 遵循项目现有分层与命名；业务逻辑不写在 controller / handler 里
- DTO 与领域模型分离；不把数据库实体直接暴露给接口
- 配置走配置文件/环境变量，不硬编码

正确性：

- 每个接口按契约返回；字段名、类型、错误码与 `design.md` 一致
- 参数校验在入口完成，业务校验在 service 完成，失败返回契约定义的错误码
- 每个写操作有明确事务边界；多表写入在一个事务或有补偿
- 并发修改有保护（版本号/锁/唯一约束），重复提交幂等
- 列表接口必须分页且有上限；批量操作有数量上限

安全：

- 每个接口都有鉴权；每个资源操作都校验归属（不能只校验登录）
- 不拼接 SQL；不信任前端传来的 ID 归属
- 敏感字段（密码、token、手机号）不出现在日志与响应

可观测：

- 关键操作有结构化日志（谁、对什么、结果、耗时）
- 错误日志带上下文（请求 ID、参数摘要），不吞异常

数据：

- 迁移脚本可在干净环境执行、可回滚；不手改线上表
- 索引覆盖查询条件；避免 N+1（用 join / batch / dataloader）

测试：

- 业务规则有单测（含边界值）
- 接口有正反例测试：正常、参数错误、无权限、资源不存在、重复提交、并发冲突
- 测试数据自建自清，不依赖外部环境状态

洁净：

- 无 TODO / 占位实现 / 写死的返回值 / 注释掉的代码
- 无未处理的 warning；lint 通过

## 接口验证流程（接口任务标 `已完成` 前必做）

1. 启动服务（或运行接口测试），对本任务的每个接口执行：
   - 正常请求 → 响应结构与示例一致
   - 缺参 / 错类型 / 超范围 → 返回契约中的参数错误码
   - 未登录 / 无权限 / 访问他人资源 → 返回契约中的鉴权错误码
   - 资源不存在 → 404 类错误码
   - 重复提交 → 幂等或返回冲突错误码
2. 涉及写操作：检查数据库中的记录、状态、时间戳、审计字段
3. 涉及状态机：验证非法迁移被拒绝
4. 涉及迁移：在干净数据库上执行迁移与回滚
5. 跑项目全部测试与 lint
6. 在 record 中记录实际执行的命令与关键响应
7. 任一项不通过，不得标 `已完成`

## 反模式

- 先写实现再补契约；前端靠猜字段
- 只校验登录不校验归属
- 列表不分页、批量无上限
- 捕获异常后吞掉或只打印
- 写操作无事务、多表写入部分成功
- 用业务代码模拟唯一性而不建唯一索引
- 返回值写死为演示数据
- 错误码随手编，与 common 不一致
- 只测 happy path
