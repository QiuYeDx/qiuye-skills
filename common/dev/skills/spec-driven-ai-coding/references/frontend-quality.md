# 前端质量：按本次 UI 影响使用

## 设计需要回答的问题

界面入口、目标用户、主操作、信息层级是什么？复用哪些现有组件/token？状态在本地、URL 还是全局？数据来自哪个真实契约？
写清有变化的交互、表单校验、错误反馈、导航、焦点与键盘行为。无需重新抄项目全部样式规范和每个未变化按钮文案。
无设计稿时给出简短布局/视觉基准或轻量原型；涉及产品取舍请确认，不为一个微调补全十项大表。

## 状态按维度列，不机械套五态

异步数据可能有 idle/loading/success/error；数据内容可能 empty/nonempty/partial；权限可能 allowed/denied；操作可能 enabled/disabled/pending。
这些维度可以组合，不是五个互斥状态。选择本次组件/页面真正存在且有风险的组合，定义行为并验证。
静态展示组件不必凭空增加 loading 或无权限态。已有数据刷新失败时是否保留旧结果，应依项目契约明确。

## 实现重点

沿用组件库、token、表单方案与语义元素。新增样式有明确目的；不将“禁止魔法数字”当作完全禁止局部几何计算。
异步提交避免重复操作，失败保留输入，反馈与错误可理解；权限禁用/隐藏遵循需求。
导航、筛选、分页、排序是否同步 URL、是否返回保留，按现有行为和需求决定，不自动发明持久化需求。
焦点可见，按钮有可读名称，弹层焦点管理正确；可访问性属于设计/实现底线，不留到最后统一补。
动效服务反馈和连续性，遵循 reduced-motion；时长由交互与项目规范决定，不用一个固定区间否定所有场景。
大数据场景测量内存/渲染/交互再选虚拟化、Canvas/WebGL 等方案，不把某一优化当作通用必选项。

## 浏览器验证

按实际能力启动开发/预览环境，核对数据与路由。用合成或获准的测试数据走本次主流程和适用异常。
通过受控 fixture/请求拦截/测试账号验证错误、权限和延迟；不要清空生产数据或故障注入真实服务。
检查受影响断点、键盘/焦点、控制台新增问题和布局；截图/录屏/测试报告附版本、环境与可定位路径。
已有第三方警告与本次新增错误区分记录，不为了“零警告”修改无关模块。
仅阅读源码或截图不能替代实际交互验证。无浏览器时做可做的静态/组件测试，明确未执行浏览器步骤，保持待验证。

## 范围与复用

对 UI 做结构/交互修改时要求浏览器证据；纯文案/纯类型等变更可按风险采用更小验证范围，记录理由。
已有成熟组件仅改调用处时，验证本次集成状态，不重新测试组件内部所有能力。
项目已安装的专门 UI Skill 可按需读取；不存在的 Skill 内容不能臆造。
