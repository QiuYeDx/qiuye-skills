# 前端质量基准

前端粗糙的根因通常是「没有设计阶段就直接写代码」和「没在浏览器里看过就交付」。本文件规定设计阶段必须产出什么、实现必须达到什么、交付前必须怎么自检。

## 设计阶段产出要求（写入 design.md「前端设计」）

每个涉及 UI 的模块必须写全以下 10 项，缺一不过设计门：

1. **页面/视图清单**：路由、入口位置、所需权限、对应的用户场景与 R 编号
2. **信息架构与布局**：每页的区域划分（ASCII 线框或分区列表）、主操作位置、信息层级（一眼先看到什么）
3. **组件树与复用**：优先复用项目组件库，列出具体组件名；需新建的组件写职责、props、受控/非受控
4. **状态设计（五态）**：loading（骨架屏还是 spinner、放哪）、empty（文案 + 引导动作）、error（文案 + 重试方式）、success/正常、partial/disabled；表单再加 校验中 / 提交中 / 提交失败
5. **交互细节**：每个可点击元素点击后发生什么；表单字段校验规则与错误文案；破坏性操作的二次确认与后果说明；成功反馈方式（toast / inline / 跳转）；键盘操作；多选与批量操作
6. **数据流**：数据来源接口（引用契约）、状态放在哪（局部/全局/URL）、缓存与刷新策略、是否乐观更新、并发编辑处理
7. **响应式**：断点与各断点下的布局变化；不支持移动端时明确写出
8. **文案清单**：标题、按钮、空态、错误、确认框、成功提示（按语言约定，全部列出）
9. **可访问性与动效**：焦点顺序、图标按钮的 aria-label、颜色对比；动效目的、时长、是否响应 `prefers-reduced-motion`
10. **视觉基准**：遵循项目设计 token / 主题；无设计稿时描述密度、圆角、阴影层级、强调色使用规则

## 实现基准

布局与视觉：

- 只用设计 token 与项目的间距/字号阶梯，禁止魔法数字
- 对齐一致；层级由字号、字重、颜色共同表达，不靠加粗一切
- 卡片、分割线、边框不过度嵌套；密度与数据量匹配（数据表用紧凑密度，表单用舒适密度）
- 同一模块内相同类型的元素外观一致

组件：

- 复用项目组件库；不重复造轮子；表单用项目既有的表单方案
- 不用浏览器原生 `alert` / `confirm` / `prompt`

五态：

- 每个列表、详情、表单都能触发 loading / empty / error 并有对应 UI
- loading 用骨架屏或占位保持布局稳定，避免闪烁
- empty 有说明与下一步动作；error 说明原因与可做什么（重试、返回、联系）

表单：

- 失焦或提交时校验，错误信息紧贴字段
- 提交中禁用按钮并显示进度；失败保留用户输入；成功有明确反馈
- 必填、格式、长度、范围校验与接口契约一致

表格/列表：

- 分页、排序、筛选状态可保持（刷新或返回后不丢）
- 长文本截断 + tooltip；操作列固定；行操作有 hover 反馈
- 批量操作先选后操作，有数量提示与确认

反馈与导航：

- 成功提示短暂、非阻塞；错误提示说明原因与下一步
- 破坏性操作二次确认并说明后果
- 当前位置高亮、可返回；有未保存改动时离开需提示

响应式与可访问性：

- 在设计声明的断点下不破版
- 可键盘操作、焦点可见、图标按钮有 aria-label、颜色对比达标

动效：

- 150–300ms；有目的（反馈、方位、连续性）；尊重 `prefers-reduced-motion`
- 不做炫技动效；不阻塞用户操作

文案：

- 遵循语言约定；动词开头；错误文案说原因和下一步
- 无 lorem、无占位图、无「敬请期待」

洁净与性能：

- 无 `console.log` / `debugger`、无未用变量与死代码、TS 不滥用 `any`
- 列表 key 稳定；避免不必要的重渲染；大列表虚拟化；图片给尺寸

## 浏览器自检流程（UI 任务标 `已完成` 前必做）

1. 用项目命令启动开发服务器，打开本任务涉及的每个页面
2. 用真实形态的数据（不是 `test`、`111`）走完该任务关联需求的主流程
3. 逐一触发五态：清空数据看 empty、断网或让接口返回错误看 error、限速看 loading、无权限看 disabled/隐藏
4. 缩窄到设计声明的最小断点检查布局
5. 控制台零错误零警告；第三方无法消除的警告在 record 说明
6. 对照 `design.md`「前端设计」逐项打勾；不一致则改代码，或先改设计再改代码
7. 有浏览器工具或截图能力时截图存档或贴回复；没有则在 record 描述观察到的结果
8. 任一项不通过，不得标 `已完成`

## 反模式

- 只做 happy path，empty / error 不处理
- 硬编码演示数据、按钮无功能、点击无反馈
- 每页风格不同、自造样式而不用组件库
- 表单无校验或校验只在控制台报错
- 缺少加载态导致闪烁或重复提交
- 动效时长 >500ms、无 reduced-motion、纯装饰
- 所有内容一样大小一样颜色，无层级
- 交付前没在浏览器看过

## 可选参考 Skill

若环境已安装，设计或实现阶段可读取：`frontend-pitfalls`（CSS/交互坑位）、`motion-recipes`（Motion 动效模板）、`emil-design-eng` / `apple-design`（细节与手感）、`qiuye-smooth-corners`、`qiuye-edge-gradient-mask`。不存在则跳过，不要臆造其内容。
