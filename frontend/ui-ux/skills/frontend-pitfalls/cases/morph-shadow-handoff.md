# Case 3: 容器变形过渡中的阴影交接

## 目标

卡片展开成居中浮层、按钮变形成面板、图片放大成灯箱等容器变形过渡（Container Transform）中，让浮层与原始元素之间的阴影连续过渡，避免：

- 收起落地的最后一帧，浮层的重阴影突然变成卡片的轻阴影。
- 展开第一帧，重阴影直接以满强度出现。
- 落地时阴影轮廓、颜色或扩散与卡片略有差异，交接时「跳一下」。

## 适用场景

- 卡片 → 详情浮层、列表项 → 居中面板、FAB → Dialog、缩略图 → 灯箱。
- 浮层使用与触发元素不同的阴影（浮层需要更强的悬浮感）。
- 用户反馈「收起结束时阴影突然消失 / 变轻」「展开一开始阴影就很重」「落地时闪一下」。
- 动画几何（位置、尺寸、圆角）已经连续，但交接那一帧仍有可见跳变。

## 核心判断

容器变形通常由两个元素接力：飞行中的浮层（或视觉克隆）和留在原位的触发元素。交接发生在浮层卸载、触发元素恢复显示的同一帧。几何已经对齐，但**阴影往往不在动画范围内**：浮层固定使用重阴影，卡片使用轻阴影，交接帧就会跳变。

阴影要做到连续，需要同时满足两点：

1. 浮层在落地时的阴影与触发元素**逐值一致**，最好共用同一个定义。
2. 浮层额外的「悬浮阴影」随飞行变化，并在落地前**提前归零**。

## 排查顺序

1. 找出浮层与触发元素各自的 `box-shadow`（含 hover 态），确认是否相同。
2. 检查浮层的阴影是否是静态 CSS，没有参与开合动画。
3. 若已在动画阴影，检查它是否与几何动画共用同一条 spring：spring 的长尾会让阴影在落地时仍残留少量强度。
4. 若阴影放在独立的柔影层上并用 `opacity` 淡出，检查卸载前后是否有一帧闪回（见坑 4）。
5. 落地前后各取一帧，比较浮层与触发元素的 computed `box-shadow` 字符串。

## 推荐结构

```text
触发元素（卡片）      box-shadow: var(--rest-shadow)
浮层（飞行 / 停靠）   box-shadow: var(--rest-shadow),
                                 <深阴影，强度 × var(--lift)>
--lift: 0（与卡片重合）→ 1（完全展开）→ 0（落地前归零）
```

- 静止阴影抽成一个共享变量，两端都只引用它，不复制数值。
- 悬浮阴影作为第二层叠加，用一个 0–1 的 CSS 变量控制颜色透明度。
- `--lift` 由动画库驱动：展开时随飞行增强；收起时用比几何动画更短的时长提前归零。

## 推荐实现模板

```css title="card-morph.css"
/* 两端共用同一个静止阴影，落地时轮廓完全一致。 */
.card,
.sheet {
  --rest-shadow: 0 4px 20px -12px
    color-mix(in oklab, var(--foreground) 14%, transparent);
}

.card {
  box-shadow: var(--rest-shadow);
}

.sheet {
  --lift: 0;
  box-shadow:
    var(--rest-shadow),
    0 40px 100px -40px rgb(0 0 0 / calc(0.5 * var(--lift)));
}
```

```tsx title="Sheet.tsx"
const SHEET_SPRING = { type: "spring" as const, duration: 0.5, bounce: 0 };
const EASE = [0.22, 1, 0.36, 1] as const;

<motion.div
  className="sheet"
  initial={{ ...fromRect, "--lift": 0 }}
  animate={{ ...(expanded ? targetRect : fromRect), "--lift": expanded ? 1 : 0 }}
  transition={{
    ...SHEET_SPRING,
    // 收起时比几何动画更早归零，让卡片的静止阴影无缝接手。
    "--lift": reduceMotion
      ? { duration: 0 }
      : { duration: expanded ? 0.45 : 0.32, ease: EASE },
  }}
/>
```

## 常见坑与修复

### 坑 1: 浮层固定使用重阴影

错误模式：

```css
.sheet {
  box-shadow: 0 40px 100px -40px rgb(0 0 0 / 0.5);
}
```

原因：

- 阴影不参与动画：展开第一帧直接以满强度出现，收起落地时浮层卸载，卡片的轻阴影在同一帧接手，强度骤降。

修复：

- 拆成「共享静止阴影 + 受 `--lift` 控制的悬浮阴影」两层，见推荐结构。

### 坑 2: 两端阴影「看起来一样」但不是同一个值

错误模式：卡片写 `0 4px 20px -12px color-mix(...)`，浮层另写一份近似值，或一端用 `rgba()`、另一端用 `color-mix()`。

原因：

- 偏移、模糊、扩散或颜色任何一项不同，交接帧都会有细微跳变，深浅两种主题下的差异还可能不同。

修复：

- 抽成一个共享 CSS 变量，两端只引用变量。
- 验收时比较 computed `box-shadow` 字符串是否逐值相同。
- 注意触发元素的 hover 阴影：浮层落地时若指针仍停在卡片上，卡片会以 hover 阴影出现。需要完全一致时，让交接后的卡片先显示静止阴影，再由 CSS transition 过渡到 hover 阴影。

### 坑 3: 直接动画 `box-shadow` 字符串

错误模式：

```tsx
animate={{ boxShadow: expanded ? HEAVY_SHADOW : "var(--rest-shadow)" }}
```

原因：

- 动画库只能插值结构相同、数值可解析的阴影字符串。`var()`、`color-mix()`、层数不同的阴影无法插值，结果是直接跳到终值，或报插值警告。

修复：

- 阴影结构固定写在 CSS 中，只动画一个数值型 CSS 变量（`--lift`），用 `calc()` 作用在颜色透明度上。

### 坑 4: 用 `opacity` 淡出独立的柔影层，卸载前后闪一帧

错误模式：在浮层外放一个跟随飞行的柔影 div，用 `opacity` 1 → 0 淡出，落地时与浮层一起卸载。

原因：

- Motion 等库会把 `opacity` 交给 WAAPI（合成器）执行，元素的内联样式停留在起始值。动画结束到库写回最终值之间可能隔一帧，恰好与 React 卸载 / 重渲染重叠时，这一帧会显示过期值：退出的层闪回不透明，进入的层闪成透明。

修复：

- 改为动画 CSS 变量（如 `--lift`），由 `opacity: var(--lift)` 或阴影颜色透明度引用。CSS 变量不走 WAAPI 加速，每帧都由 JS 写入，不会出现过期帧。
- 或者把阴影直接放在浮层自身的 `box-shadow` 上（推荐结构），不再需要独立柔影层。
- 浮层有 `overflow: hidden` 时，不要把阴影放在它的伪元素或子元素上：子元素的阴影会被裁掉；元素自身的 `box-shadow` 不受自身 `overflow` 裁剪。

### 坑 5: 阴影与几何动画共用同一条 spring

原因：

- spring 收尾很慢，几何视觉上已经落地，`--lift` 却还有少量残余；卸载那一帧仍会有轻微跳变。

修复：

- 给 `--lift` 单独设置更短的 tween（如展开 0.45s、收起 0.32s，ease-out），保证收起时先于几何动画归零。

## AI Agent 执行步骤

1. 找出变形过渡中的两个端点（触发元素、浮层 / 克隆），列出它们静止态与 hover 态的 `box-shadow`。
2. 把触发元素的静止阴影抽成共享 CSS 变量，浮层引用同一变量作为第一层。
3. 为浮层增加第二层悬浮阴影，颜色透明度乘以 `var(--lift)`，并给 `--lift` 设默认值 0。
4. 在动画库中让 `--lift` 随开合变化，并为它设置独立的、比几何动画更短的时长。
5. 若项目已有独立的柔影层，改为 CSS 变量驱动，或合并到浮层自身阴影中。
6. 减少动态效果模式下，`--lift` 与浮层同步出现 / 消失，不保留飞行过程。
7. 按验收清单逐帧检查展开第一帧、收起最后一帧与交接帧。

## 验收清单

- 展开第一帧，浮层阴影与触发元素相同，不是满强度的重阴影。
- 展开过程中悬浮阴影逐步增强，完全展开时达到设计强度。
- 收起过程中悬浮阴影逐步减弱，在几何落地前归零。
- 浮层最后一帧与触发元素恢复显示后的 computed `box-shadow` 逐值一致。
- 浅色、深色主题都检查过交接帧。
- 阴影没有被浮层自身的 `overflow: hidden` 裁掉，也没有使用 WAAPI 加速的 `opacity` 淡出后再卸载。

## 推荐回答格式

完成修复后向用户说明：

- 原先两端的阴影分别是什么，跳变发生在哪一帧。
- 静止阴影如何共享、悬浮阴影由哪个变量控制，以及时长设置。
- 逐帧验证的数据（如 `--lift` 序列、交接帧前后的 computed `box-shadow`）。
