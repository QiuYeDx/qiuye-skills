# 行为评估场景

用于检查 Skill 是否能改变决策，不是 UI 项目的强制测试套件，也不是已运行的模型基准。

评估时给执行者当前 Skill、相应用户请求和最小原始代码/截图，不预先告知缺陷或解法。允许修改的场景用隔离目录；不得发真实消息、调用付费模型接口或改用户生产数据。评估结果分别记录“方向正确”“发现问题”“修复有效”“证据充分”，不要合成虚假的审美总分。

| 场景输入 | 应观察到的行为 | 失败表现 |
| --- | --- | --- |
| 已有蓝绿色工具产品，用户要求达到 Apple 级质量 | 阅读认可页面和组件，保留本产品语言，改善工作流与细节 | 擅自改成暖色编辑器、苹果官网或大幅宣传式布局 |
| 用户只要求修正一个 Tooltip；两行短但框宽，含 balance 默认值 | 打开并测量内容，局部修复换行/尺寸，验证长短文案 | 全局禁用 balance，重写全部 Tooltip，或只断言 visible |
| 表格中一条长正文，时间和复制按钮随整行居中 | 发现关联列对齐，按内容增长当前行，复验相邻短行 | 设置所有行固定很高，或截掉长正文 |
| 文件信息占三层高度、右侧大片空白，正文首屏只剩少量行 | 检查纵向预算与横向利用，重排元数据并比较可见内容 | 只调色彩、缩小字体，或因没有溢出判定通过 |
| 靠圆角按钮上方 12px、右侧 16px，邻近面板统一紧凑尺度 | 量相邻两边并选合理的等距值，检查内外曲线和邻近面板 | 只统一同方向边距，或总增大较小值而加剧松散 |
| 分页栏明显过高；压缩后末端按钮距底 4px、距侧 12px | 同时处理高度与靠角等距关系，保留热区，复验首尾页和焦点 | 只压 py 或只加 py，解决一个问题后不检查另一个 |
| 内外嵌套圆角相同、四边数值相等，但转角空白不均匀 | 看曲线关系，依据实际形状调整内外圆角或间隔 | 仅因 p-* 相同就通过，或把圆形公式硬套所有平滑圆角 |
| 共享配置面板 padding 改小，分隔线仍负向外扩 | 找到补偿负 margin 和消费页覆盖，一并调整后验证展开态 | 只改 padding 并称单元测试通过 |
| 文档列表选中第 1 项，hover 第 2 项 | 检查组合状态、离散背景和键盘焦点 | 单独截选中态，或禁止 hover 以隐藏问题 |
| 同一对象的激活、选择和焦点各自呈现正常，组合时多个表面争夺强调 | 明确状态语义与优先级，检查实际绘制范围，保留独立反馈 | 只逐个测试状态，或禁止所有嵌套表面、删除焦点来消除冲突 |
| 操作或提示区域出现后，正在使用的工作区重排 | 比较转换前后目标、内容、滚动和焦点，判断重排是否妨碍任务 | 只检查新区域可见，或强制所有界面使用固定栏、固定高度和零位移 |
| 文件名只在尾部有版本和扩展名差异 | 保留识别段和完整信息入口，测试 Unicode/窄宽度 | 固定字符数末尾截断、切坏字符、短名称被截断 |
| 新建艺术展览站点，没有既有工具页参照 | 依据内容和受众决定视觉，保留需要的展示留白 | 将此 Skill 误读为所有站点都用紧凑 12px 工具布局 |
| 已有项目明确要求 pill 参数切换，但另一产品喜欢矩形 Tab | 遵循当前需求和控件语义 | 把另一产品的视图 Tab 偏好套到所有选择控件 |
| 原生壳有加载层和固定导航，DOM 已存在 | 等真实就绪、检查截图内容及遮挡，清理测试实例 | 把 loading / 被挡住的截图或模拟壳称为原生验证通过 |
| 无法运行目标平台，只有源码和截图 | 完成可做的分析/修复，明确验证限制 | 谎称视觉验收通过，或完全停工等待用户逐项指导 |
| 用户明确只要只读评审 | 有依据地指出问题，遵守不修改要求 | 以自动修复流程为理由改源码 |
| 首次实现已经符合参照且相关检查通过 | 完成独立审查后交付，无需制造额外改动 | 为达到固定轮数不断重写或跑全量测试 |

实际效果应在后续 UI 任务中记录：首轮人工发现的缺陷、遗漏属于哪个状态、哪些共享规则有效、验证成本。该数据才能支持“减少人工返工”的结论；结构校验、规则走查和测试数量不能单独证明它。
