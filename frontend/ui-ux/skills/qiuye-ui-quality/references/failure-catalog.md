# 常见失误与修复

按涉及的组件阅读。表中的方法可通用，具体数值和视觉选择必须来自当前项目。

## 为什么能写出来，却仍然需要反复人工纠偏

本组经验来自一个字幕工作台及其同项目工具页的连续 UI 改进，不是关于所有模型的对照实验。能从已观察过程确认的是：

| 失误机制 | 人工反馈补上了什么 | 应前置的动作 |
| --- | --- | --- |
| “专业”被转译成常见设计模板，没有先确认本产品的视觉语言 | 明确指出风格不属于本项目 | 先看已认可页面和真正复用的组件 |
| 以组件存在、能点击、构建通过作为完成标准 | 指出信息密度、空白与对齐不合理 | 把视觉关系列为单独的验收对象 |
| 用短假数据、空状态和默认窗口评估布局 | 提供真实长文件名与实际窗口截图 | 先准备真实内容和对布局不利的样本 |
| 修复一次只关注用户圈出的点 | 继续指出相邻区域和其他页面的同源问题 | 搜索共享样式与调用侧覆盖，复验授权范围内的同类实例 |
| 熟悉组件名称，却没有检查默认 variant 和继承行为 | 指出 Tab 形状、Tooltip 换行与宽度不对 | 看最终 computed style 和打开后的组件 |
| 自动测试验证的是“存在/可见”，不是用户指出的视觉性质 | 发现“Tooltip 测试通过”仍有大块空白 | 为失败性质选断言，并人工式审阅最终截图 |

人工意见逐渐把模糊目标变成具体参照、约束与反例，减少了实现搜索空间。自主复查应模拟这一过程；同一个模型仍可能保留盲点，不能承诺完全取消人类验收。

## A. 风格与组件

**现象**：单页很精致，但像另一款产品；同名组件用了不同的 shape / size。

**排查**：比较已认可页面的布局、字体、色彩、圆角、密度和控件状态，再读实际组件默认值、主题 token 与调用参数。区分产品有意区分的区域，不机械统一所有外观。

**修复**：优先复用原有呈现层及明确变体；若需要新结构，保持它与现有视觉层级的关系。项目原本允许的胶囊参数选择器，不应因另一处 Tab 被改成矩形而全部替换。

**验收**：在同一窗口、主题和数据规模下并排比较目标页与参照页；检查选择、焦点和禁用态。

## B. 间距与信息分配

**现象**：工具栏上方窄、右侧宽；刷新图标看似歪；元数据几行堆叠，占掉正文空间。

**排查**：把最终间距分解为外层 padding、子容器 margin、gap、按钮内部留白、边框和图标字形。区分计算边界与光学边界，不从截图物理像素直接推导 CSS px。

**修复**：同类区域使用项目一致尺度；合并不必要的元数据层级，让标题、必要摘要和操作合理共享横向空间，窄时再换行。减少留白前保留触摸/键盘目标和阅读所需行距。

**空间预算**：从视口高度扣除壳层、页面标题、上传区、元数据、Tab、表头与底栏，检查实际剩余正文高度；再看横向列宽与空闲空间。逐层“只多留一点”叠加后可能使工具失去可用内容区。分页栏高度由控件和必要内边距决定，不继承正文的大片留白；计数增加到多位、操作换行时再验证。

**反例**：看到顶部 12、右侧 16，不应条件反射地把顶部加到 16；先看项目尺度、邻近面板和页面密度。局部等边距与整页一致性必须同时成立。数字只用于说明关系，不是通用设计常量。

### B1. 圆角附近的横纵留白不等

**现象**：所有数值都来自 spacing token，但右上角按钮离上边近、离右边远，或分页按钮距底边很近、距侧边很远。圆角把两条边连接起来后，差异尤其显眼；这不是只有“边距混用”才会出现的问题。

**修复**：对靠角元素，先把其可见外框到容器相邻两条内边界的留白设为相等，再看曲线间的负空间。右上角比较上/右，右下角比较下/右，左侧同理。检查实际父子层级、border、margin、行高和控件尺寸；只设容器 `p-*` 可能仍不等距。不能以“footer 通常横向宽、纵向窄”为理由忽略靠角按钮的关系，也不要一律加大纵向留白而把底栏再次撑高。

**圆角关系**：同心普通圆角嵌套时，内圆角半径约为外圆角半径减去两轮廓间距，可作为几何起点，不是所有按钮必须套用的公式。独立按钮、不同形状及 superellipse/smooth corners 必须看最终曲线；内外直接用相同的大圆角，常会在转角处产生不均匀空隙。

**验收**：同时看页面上下文和圆角局部截图；先量相邻两边距离，再看曲线。图标字形、透明点击区域和焦点环另行判断，不能用所谓光学修正掩盖按钮外框明显不等距，也不能缩小热区或裁掉焦点环。项目明确的非对称构图可以保留，但不能把未审查的旧数值当成这种设计依据。

**共享组件陷阱**：减少父级 padding 后，原来用于通栏的负 margin、折叠内容、底栏和页面覆盖也需重新检查。避免子面板中再叠一层相同装饰容器，或靠多个相反 margin 偶然抵消。

**验收**：测控件外框到面板内容边的距离，对比同类控件；确认操作点击区域不缩小，信息没有被裁掉，首屏有效内容增加。

## C. 密度、多行与稳定对齐

**现象**：一个索引对应的内容只一行，却占很高；一列换行，其他列垂直居中后跳位置。

**排查**：行 min-height、line-height、上下 padding、操作按钮高度、表格 `vertical-align`、flex 的 `align-items`。时间区不必要的两行也会撑高整行。

**修复**：依据内容与可访问性目标确定一行高度；比较型数据行用顶部对齐，允许长内容自然增加本行高度。行内操作可以缩小视觉尺寸，但不能使目标不可点。不要全局强制所有列表顶部对齐，例如头像标题行可能需要居中。

**验收**：在同一列表中放一行、自动换行、显式换行及很长的无空格字符串；比较编号、时间和操作相对行顶的偏移。验证复制、选择、滚动和最后一页。

## D. 文件名与完整信息

**现象**：省略号删掉了区分文件的尾部，短名称也被截断，Tooltip 只有鼠标能触发。

**修复选择**：文件名通常保留开头、结尾和扩展名；其他数据按含义选择保留段落，不对全部文本套中间省略。优先使用经过验证的项目组件；CSS 分段应允许前段收缩，同时为尾段设合理上限，极窄容器仍需可用的完整信息入口。

**注意**：字符数不是像素宽度；固定截取 N 个字符无法响应中文、英文、窗口变化。程序截断时考虑 Unicode 字符/字素簇，不能切坏代理对或组合字符。不要把两个半字符串变成两份可读名称；完整名称须对辅助技术可用，避免嵌套交互元素。

**验收**：短名称不截断，长名称可识别尾部，窗口变动不溢出；悬停和对应键盘焦点能取到完整信息，触摸场景有合适替代入口。

## E. Tooltip 的框不是文字

**现象**：长名称提示框很宽，文字却早早换行，右侧整块空白。

**原因候选**：继承的 `text-wrap: balance`、固定/最小宽度、内容 `max-width` 与外框尺寸不一致、隐藏的无障碍副本参与布局。`max-width` 只限制上限，不保证文字填满。

**修复**：短提示按内容收缩；长标识符使用项目适合的宽度上限、正常换行和窄视口约束。需要任意位置断行时考虑 `overflow-wrap: anywhere`。不要把标题适用的均衡换行无条件用于文件名提示，也不要全局禁用均衡换行。

**验收**：真正打开提示，等字体及过渡稳定，再看短名称、长中英混合名称、无空格标识符和靠近窗口边缘的触发器。比较外框与最长可见文本行的边缘；末行自然留白不是缺陷，多行都只占框的一部分才需要追查。确认 Escape、失焦/移出及移动到提示内容的行为符合所用组件。

## F. 单个状态好看，组合后出错

**现象**：选中项与相邻 hover 项的背景连成一块；透明 hover 状态看不清；切换 Tab 后行高改变。

**修复**：确认列表是否需要离散项或连续选区。需要离散项时用真实行间 gap / inset 保持间隔；不要用边框颜色遮住选中状态。为反复出现的控件、计数和加载态保留稳定尺寸。

**验收**：选中+相邻悬停、选中+焦点、禁用+悬停、首尾项与滚动边界一起看。控件切换前后量周边位置，确认点击目标未移动。

## G. 图标、动作与语言

**现象**：箭头方向与“导入/导出”等文案让人误判；只更新一种语言；图标按钮没有可访问名称。

**修复**：依据数据流和项目词汇确定动作语义，图标与文案作为一组审核。改变显示文案不要求重命名稳定业务 API。不要为了某个箭头强行改成不符合真实行为的“上传到云端”。

**验收**：实际执行动作、取消和错误恢复；检查相同动作的按钮、Tooltip、通知和相关语言，确认短文案仍易于理解。

## H. 看似充分的验证

**现象**：大量截图或测试通过，用户仍立即发现问题。

**排查**：截图是否确实是最终代码、正确数据、稳定状态？是否真的打开过浮层？是否只测 `visible`、`overflow=false` 或类名？是否被全局 loading、固定导航或截图裁剪隐藏？

**修复**：用对应故障的反例验证断言有检测能力。样式类名、最大宽度和“按钮能点”是辅助证据；还需要相关状态的视觉观察。发现相同截图没有随滚动变化时定位真实滚动容器，不重复生成无效证据。
