# 原生滚动控制权交接

## 需要解决的真实冲突

Lenis 惯性尚未结束时，异步代码调用原生 `scrollTo({ behavior: "smooth" })`。浏览器还没产生首个 scroll 事件，Lenis 下一次 instant 写入就可能取消该原生动画。只比较 scrollY 或等待 scroll 事件不能完整解决这个时序。

## 两种选择

**可维护所有滚动调用点的项目：** 使用明确的统一滚动入口，在调用原生方法前先取消引擎惯性，或让引擎直接负责程序化滚动。此时保持 nativeScrollInterop 关闭，但要把取消能力暴露为项目 API 并接入真实调用点；模板默认只返回 dispose，需要按此选择扩展。普通点击捕获并不能覆盖定时器、网络回调等异步调用。

**已有大量业务/第三方原生调用且需要保持原调用形式：** 在已说明实现选择后启用模板 nativeScrollInterop。参数、this 和返回值原样转发；开始外部请求前取消惯性。此选择属于方法包装，不能称为纯配置或零侵入。

## 包装模板的约束

- 包装 window.scroll/scrollTo/scrollBy，以及 Element 的相应根滚动调用和 scrollIntoView。普通嵌套元素 scrollTo 不需要终止页面惯性；scrollIntoView 可能同时影响祖先滚动。
- Lenis 自身写入也经过 window.scrollTo，必须用 advancing 标记跳过取消逻辑，并在 finally 中复位；否则会递归或自行停止。
- 保存方法和属性描述符；cleanup 只恢复仍由自己持有的方法，不覆盖后来其他代码的替换。
- 模板假定标准、可配置的浏览器属性与单一安装者。若遇冻结原型、其他方法包装或多应用并存，先检查描述符/所有权；不能静默宣称成功。需要时实现安装失败回滚，或改用显式统一入口。
- 方法引用与 toString 等身份特征会改变。预先保存原始函数引用的第三方代码可以绕过包装，iframe 也有独立 realm；不承诺覆盖这些路径。
- 非法参数、坐标重载、options 形式的错误/返回行为应由原始方法负责。避免重新实现参数解析或强制把 smooth 改成 instant。

## 按需 RAF 的已知陷阱

事件回调的 performance.now() 可以晚于当前帧 RAF 时间戳；把前者写进引擎再减后者会产生负时间步长，出现首个 wheel 被拦截但页面不动。基线 Lenis 1.3.23 使用 time = 0 在第一帧重建时钟。新版本须核实实现，不依赖未经验证的内部字段。

嵌套滚动是否由 Lenis 消费是在 virtualScroll 回调之后决定的；模板在 microtask 中检查事件状态，再唤醒或释放。若其他 window 监听器也会 preventDefault，需验证执行顺序，优先用明确的锁信号/防拦截标记，不把 defaultPrevented 当作可靠的全局所有权协议。

## 验证边界

测试必须在惯性**进行中**调用原生 API。只测试页面静止时回顶不能证明兼容。并验证卸载恢复、Strict Mode、路由切换后没有多个包装层争抢。新滚动引擎或自定义根容器不能直接复用 window 专用的所有权判断。
